## 北極星

最大化するのはアプリ滞在時間ではなく、**本試験での合格可能性**。主要指標は「未見または十分に間隔を空けた問題を、制限時間内・ノーヒントで正答できた割合」とする。

補助指標は次の4つ。

1. 論点別の時間内正答率
2. 7日・21日後の保持率
3. 同じ誤概念の再発率
4. 模試の得点と時間配分

連続ログイン、総プレイ時間、タップ数は合格率の代理指標にしない。

## 1セッションのループ

1. 60〜180秒の問題を出す
2. 回答を確定してから採点する
3. 正誤だけでなく、借貸・科目・計算・時間のどこで崩れたかを分類する
4. AI師匠が答えを先に言わず、誤概念を特定する短い問いを返す
5. 正答を自分の言葉で説明させる
6. 同型問題を直後ではなく、忘却リスクが高まる時点で再出題する

本試験モードではヒントとAI対話を隠す。講師モードでヒントを使った正答は「理解中」とし、本試験準備済みには数えない。

## 適応カリキュラム

次に解く問題は、概念的に次の優先度で決める。

```text
優先度 = 出題重要度 × 不合格寄与度 × 忘却リスク × 改善余地 ÷ 所要時間
```

- 出題重要度：試験範囲と過去問傾向を、年度・科目・出典付きで管理
- 不合格寄与度：その論点を落とした場合に模試得点へ与える影響
- 忘却リスク：前回学習からの経過と過去の保持率
- 改善余地：誤答が続くが、短い介入で改善可能か
- 所要時間：残り学習時間に対する費用

初期はルールベースで説明可能にし、十分な回答履歴が集まってから予測モデルと比較する。精度が上がったことをオフライン評価で確認できないモデルは採用しない。

## ゲーム設計

- 1問が1ターン。正しい根拠を示すと敵の「理解の崩し」が進む
- EXPは時間内・ノーヒント正答など、検証できる学習成果にだけ付与
- ボスは複数論点を混ぜた総合問題、模試はダンジョンとして表現
- 誤答は罰ではなく「弱点発見」として扱う
- ストリーク、ライフ、エネルギー、ガチャ、学習と無関係な通貨は使わない

## AIの責務と停止線

AIが担当するもの：

- ソクラテス式の問いかけ
- 学習者の言葉に合わせた説明
- 誤答理由の候補提示
- 例題の条件変更と追加練習案
- 1日の学習計画の説明

AIに担当させないもの：

- 正誤判定の最終決定
- 法令・試験範囲・出題実績の出典生成
- 学習履歴の正本
- 根拠のない合格確率の表示

採点は構造化された正答データと決定的ロジック、問題本文は人間レビュー済みの版を正本にする。

## Claude Codeの上に載せる構成

```text
Web UI
  -> local API / MCP server
      -> study engine（出題、採点、間隔反復、模試）
      -> SQLite（回答履歴、教材版、根拠、習熟状態）
      -> AI adapter（対話と説明のみ）
Claude Code plugin
  -> Skill: 今日の学習開始、弱点レビュー、教材取込
  -> MCP: next_question, submit_attempt, explain_misconception, session_summary
```

Claude Codeの会話履歴を学習状態の正本にせず、MCPの構造化データを正本にする。これでモデルやプロンプトを替えてもカリキュラムが壊れない。

## データの最小単位

各問題は `question_id`、科目、論点、年度、出典、教材版、問題形式、制限時間、正答、採点規則、誤概念タグ、解説、人間レビュー状態を持つ。回答は確定時点の問題版、回答内容、所要時間、ヒント数、正誤内訳、再出題予定を保存する。

過去問は出典と利用条件を確認し、原文、改変問題、AI生成例題を混同しない表示にする。税制・試験制度変更時は影響を受ける教材版を失効させる。

## 実装順

1. 現在の仕訳バトルで操作性と学習ループを検証
2. SQLiteとローカルMCPへ回答履歴を移す
3. 人間レビュー済み問題を100問投入し、論点タグを整備
4. AI師匠を接続し、答えの漏洩率と説明品質を評価
5. 10問セッション、復習キュー、週次模試を実装
6. 模試得点の改善を指標に適応ロジックを比較試験

## MVPの完了条件

- 仕訳問題100問がレビュー済みで、出典・版・誤概念タグを持つ
- 回答、時間、ヒント、問題版がSQLiteへ保存される
- 復習予定が再起動後も保たれる
- AI停止時でも出題と採点が動く
- 10問セッションをキーボードだけで完遂できる
- 模試得点または保持率が固定順カリキュラムより改善する
