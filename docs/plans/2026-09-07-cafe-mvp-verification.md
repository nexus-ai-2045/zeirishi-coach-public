# 相談ケース改訂MVPの検証記録

## 結論と境界

入口の任意自信チェックから、前払費用の相談・四択・結果開示前の自信・概念解説・教え返し・振り返り・完了まで、ローカルの一周を実装して検証した。製品全体や招待提供の完了ではない。製品要件の正本は [PRODUCT_SPEC.md](../specs/PRODUCT_SPEC.md) のまま。

今回の教材は合成ケース1件、固定理解確認のみ。未見ミニテスト、実AIの個別応答、審査済み教材、本番認証/RLS、模試に基づく合格ライン評価、招待/復旧運用は未完了。受験予定科目の複数登録や複数概念の一括チェックも次の実装範囲に残る。

Node.js 24.20.0、Next.js 16.3.4、Playwright Chromium。学習データはローカルPGlite、外部AI通信・公開はなし。

| 検査 | 結果 |

| TypeScript / 本番ビルド | 成功。6ルートを生成 |
| 単体・DB・HTTP | 40件成功。採点・版・所有者・再送・期限・自信開示順序・入力制限 |
| ファイルDB再起動 | 説明下書きと確定答案をclose/reopen後に復元 |

| 一周 | 相談→資料→四択→自信スキップ→解説→説明保存→再読込→振り返り→完了 |

## 独立レビューからの修正

- 利用者cookieを成功時に更新し、継続利用中に初回7日で本人識別だけ失う問題を修正。
- 失敗した保存要求の後に編集があれば、古い要求の再送で新しい説明を消さず、保存状態との比較へ戻す。
- 比較中は自動保存を止め、「手元の説明を保存する」「保存済みの内容を使う」の選択後に進む。
- 自信ありの概念を推薦から外しても、概念一覧と直接開始を維持。
- 四択はクリック直後に選択表示。サーバー保存未確認の選択は提出できない。
- 旧UIのヘッダーが新UIにも重複する問題をlayoutの責務分離で修正。

## 視覚検証

Build Web Appsスキルに沿って、採用した2案目と最新スクリーンショットを画像として目視比較した。概念行を利用可能な1件に限定する等の意図的差分があり、原画像の全機能・全行を実装したという意味ではない。

- 採用画像: ローカル生成画像 `exec-f29678a1-f161-450b-9f59-f94b0072a82d.png`。
- 入口: `web/test-results/cafe-entry-desktop.png`、1488×1058（原画像と同寸）。
- 解説: `/tmp/zeirishi-cafe-desktop.png`、`/tmp/zeirishi-cafe-mobile.png`。
- 200%: `/tmp/zeirishi-cafe-zoom.png`。

| 比較点 | 確認・修正 |
|---|---|
| 背景と色 | 灰色の外枠を白へ修正。紺の文字、青緑の選択・主操作 |
| 配置 | 左の科目・右の本文。二重ヘッダーを除去、本文の上下中央寄せを解除 |
| 見出し | 入口「学ぶところを選ぶ」、単元「前払費用」。不要な入口装飾見出しを除去 |
| 操作 | 自信は任意、直接開始を維持。四択はnative radio。段階ごとに主操作を提示 |
| 図と文字 | 12か月を当期4・翌期8で表示し、色だけでなく月とラベルで区別 |

ファーストビューの文言差分: 画像の4概念を架空の利用可能在庫として表示せず1概念へ限定。未提供科目の「準備中」、固定教材・専門審査前の表示を追加。重複した「科目を変更」と装飾コピーは採用しない。採用案の視覚体系に沿う実装を確認したが、初見の学習者による使いやすさ・学習効果の判定は未実施。
