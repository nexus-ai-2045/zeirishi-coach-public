## ローカルでの問い返し接続

保存した説明への`AI`の問い返しもローカルで試す場合は、認証済みの`Claude CLI`が使える端末で `ZEIRISHI_FIXTURE_MODE=1 ZEIRISHI_LOCAL_CLI_PROVIDER=claude npm run dev` として起動します。送るのは保存済み説明と架空教材の要点だけです。`CLI`のツール・`MCP`は無効化され、利用不可・時間切れ時は固定の問いに戻ります。環境変数を省けば従来どおり固定の問いだけです。`Codex`切替は境界だけ用意し、実動検証は次の周回です。`AI`の返答は採点・習熟判定に使いません。

入口では簿記論の二層地図を「考え方で見る」（既定）と「試験論点で見る」で切り替え、概念・論点からカフェ店主の保険料相談へ進めます。相談からも科目内の位置へ戻れます。資料付きの4択→期間図解→自分の言葉で説明→`AI`または固定の問い→振り返りまで体験できます。地図は3概念と1件の合成ケースをつないだローカル試用版で、未接続・未審査の項目は教材を開始できません。他の10科目と未見ミニテストは準備中です。ローカル`Claude CLI`の問い返しは実動確認済みですが、専門承認済み教材での`AI`品質、本番`Auth/DB`、招待運用は未検収です。地図の閲覧や自己申告、`AI`対話を正式な習熟・合格判定に使いません。

「合格ラインと復習の根拠」から本人の正式証拠を確認できます。未登録・未確認・撤回は判定保留とし、自己申告の模試を正式証拠へ変換しません。専門確認済み文書の取込は管理用サービスに分離し、一般学習`API`から登録・更新できません。

説明を保存した後の「保存済み説明で理解を確認」は、本人・答案・教材版・保存`revision`を確認して応答します。既定は固定の理解確認で外部送信しません。ローカル開発モードで`Claude CLI`を明示設定した場合だけ、架空教材と保存済み説明を送信して問い返しを受けます。正式提供には教材利用条件・品質の確認が必要です。

「理解度を短く確認する」では、最大3問の短確認と最大8分の詳細診断を選べます。現在は承認済み診断問題が0件なので、開始せず準備中を表示します。問題を有効化した後の出題・保存・中断再開・自信確認・部分点・暫定リスクの処理は実装済みで、合成問題による隔離検査と実教材の検収を区別します。

受験予定の科目は任意で複数登録でき、今日学ぶ科目とは別に保存します。自信は科目内の一括設定・解除も可能です。「最近の学習記録」から最新20件の提出済み練習を開けます。自信を固定する前の正誤は、履歴にも表示しません。

「今週の学習計画」で週の時間を入力すると、受験予定と実在教材から計画を保存できます。説明できると回答した単元は自動で省略し、必要なら単元一覧から直接学べます。教材の手動除外と理由、再計画、再読込み、計画からの相談開始に対応しています。現在は合成教材1件だけなので、余った時間は未割当と表示します。正式な復習証拠・科目の合格判定には使いません。

「このブラウザーの学習データを管理」から、本人の学習記録を`JSON`で書き出し、確認後に削除できます。未開示の正誤や内部の再送記録は書き出しません。削除後は古いタブからの再保存を拒否し、そのために利用者識別子のハッシュと失効日時だけを保持します。正式証拠・訂正履歴・復習証拠・`AI`支援要約も対象です。月単位の個人情報を含まない費用集計は削除でリセットしません。ダウンロード済みファイルは削除されません。本番`API`も実装していますが、実クラウドでの削除・復旧、認証アカウント・バックアップの運用は未検収です。

選択肢は選択時、説明下書きは入力停止の約1.2秒後または保存ボタンでサーバーの`PGlite PostgreSQL`へ保存します。保存先は `web/.local-data/study`。ブラウザには再開用の案件`ID`だけを保存します。保存確認前にタブを閉じた入力は復元保証の対象外です。通信失敗時は入力を保持し、別タブとの競合時は比較してから保存する内容を選びます。

「続きから再開」で保存済みの段階へ戻れます。下書きは意味のある最終更新から7日で失効し、完了時に説明下書きを削除します。利用者`cookie`は`API`成功時に7日へ更新しますが、`cookie`を消すと本人として復元できません。同じデータフォルダへ複数サーバーを起動しないでください。

### 認証実装の状態

オンラインモードの入口 `/` と `/login` は認証状態を確認し、本人確認後の明示操作で既存の科目選択・計画・履歴・データ管理画面へ進みます。教材は0件なので準備中と表示し、ローカル教材への代替接続はしません。設定がなければログイン準備画面のままです。オンラインでローカル版の案件`ID`を読み書きしません。提出済み記録は履歴から、期限内の未提出案件は「回答前の相談」から開きます。後者は本人の開始・意味のある更新が新しい順で最大20件。選択済み答案は一覧に含めず、再開時に本人・教材の版・提供状況を再確認します。一覧表示では期限を延長しません。承認教材0件の現状ではオンラインの案件再開は拒否されます。

画面を開いた時の本人`ID`をオンライン操作の比較専用ヘッダーに付け、サーバーの認証済み本人と一致しなければ`DB`取得前に拒否します。ヘッダーを所有権の根拠にはしません。別タブで利用者が切り替わっても、古い入力や削除確認を新しい利用者へ適用しません。認証切れ時は入力を保持して別タブでのログインを案内します。画面終了前に保存未確認の入力は手動で控えてください。

`/api/data` の本番経路は本人の学習データだけを書き出し・確認付き削除します。認証アカウント、ログイン状態、招待情報、バックアップ、ダウンロード済みファイルは対象外です。削除後の再保存防止に本人識別子のハッシュと失効日時を保持し、同じ本人`ID`での学習再開を拒否します。再送は可能ですが、学習データ削除をログアウトやアカウント削除と同一視しません。実`DB`での運用削除・復旧検収は未完了です。

保存処理は開発用のテーブル作成と業務処理を分離し、`PostgreSQL`用トランザクション`adapter`を追加しました。認証済み`ID`の固定、同じ`transaction`での利用権確認・行ロック、全24学習/所有者/費用テーブルの`RLS`を実装しています。プロフィール・履歴・週計画・データ管理・新相談/答案・模試参考記録・正式証拠読取・説明支援・診断`API`には本番`DB`経路を接続済みです。本番設定・`RLS`の実環境適用・実サーバーでの保存/失効競合は未検証です。

新相談 `/api/cafe` は教材を版付きで注入し、保存・提出・自信固定・説明下書きの処理をローカルと共用します。教材登録の正本は `approved-catalog.ts` の `MATERIAL_RECORDS`（現在0件）。概念一覧・計画候補・相談教材はこの一か所から派生します。現在のオンライン経路は `MATERIAL_NOT_AVAILABLE` を返し、開発ケースへの代替接続はしません。問題文・選択肢・資料は公開項目だけを返し、余分な正答情報を渡しません。複数の有効教材を同一科目パックへ集約し、一覧・週計画で選んだ科目/概念/版から開始します。再開・回答は本人の保存済み教材版から解決し、提供停止版を新版へ置き換えません。旧 `/api/study` はローカル保全のままです。

登録検査は `material-registry.ts`。`active`以外を供給せず、著者とは別の専門レビュー担当、内容全体のハッシュ一致、出荷承認、用途ごとの利用条件、税法の年度・根拠日を検査します。本文・出典・概念等の審査後変更は再承認が必要です。これは実際の専門レビューや許諾を実施・証明する機能ではありません。[教材レビュー手順](../plans/material-review-workflow.md)に沿って人間が記録と権限を確認します。`AI`入力可否は別に保持し、登録した練習を正式評価へ昇格させません。

学習画面は教材の題名・相談文・判断課題・確認点・追加質問を表示し、保険料や特定の人物名を他の教材へ流用しません。期間図は教材の配分名と金額を使います。審査原稿の例外と試験形式へのつながりは、採点結果の `learningNotes` に保存して自信回答後に表示します。`AI`用根拠や内部の承認情報は返しません。補足のない旧答案へ、後から新しい説明を差し込んだり再採点したりはしません。

`PostgreSQL`接続プールと設定検査はプロフィール`HTTP`へ接続済みです。`ZEIRISHI_DATABASE_ENABLED=1` と認証設定に加え、`ZEIRISHI_DATABASE_HOST` / `ZEIRISHI_DATABASE_USER` / `ZEIRISHI_DATABASE_PORT` / `ZEIRISHI_DATABASE_PASSWORD` が必要です。任意の `ZEIRISHI_DATABASE_CA_PEM` は`CA`証明書として検査し、`TLS`の証明書検証を無効化しません。資格情報をリポジトリやログに保存しないでください。

専用ログイン `zeirishi_runtime` は未作成です。配備時には`NOINHERIT`・非管理者で、`zeirishi_app` への`SET ROLE`だけを許可し、`ADMIN OPTION`や他ロールへの直接・間接所属を持たせない設定が必要です。`Supabase pooler`のユーザー名はプロジェクト参照`ID`付き、直接接続は接尾辞なしを検査します。接続上限4本はプロセス単位で、配備全体の総接続数ではありません。実接続・ロール作成・`DB`適用は承認後の別検収です。

本番学習`API`向けの共通入口 `learner-context.ts` を `/api/profile` に登録しました。認証有効時は本人`UUID`で受験予定を保存し、ローカル`cookie`を無視します。認証と`fixture`の同時有効は拒否します。審査済み教材の正本 `approved-catalog.ts` は現在0件なので、自信チェック対象・推薦は空で返し、未審査の概念を保存しません。`Pool`だけをプロセス内で共有し、本人情報はリクエストごとに分離します。接続設定を変えた場合は `DATABASE_RESTART_REQUIRED` とし、プロセス再起動が必要です。外部接続・配備・学習本体の本番化はまだ完了していません。

同じ共通入口を `/api/history` と `/api/plan` にも接続しました。履歴は本人の最新20件に限定し、自信固定前の正誤を伏せます。週計画は本番用の実案件在庫を明示的に受け取り、現在の0件では時間を未割当として保存します。`developmentOnly: false` はオンライン本人用経路を示すもので、記録を正式評価へ昇格させる意味ではありません。合成ケースの履歴は `practice_only` のままです。

`Supabase`公式`SDK`による認証確認 `/api/auth/session`、`Magic Link`要求 `/api/auth/request`、`PKCE`受取 `/api/auth/callback`、現在のセッションのログアウト `/api/auth/logout` と、本人だけが利用権を参照できる`RLS`の宣言`SQL`を追加しています。[ログイン画面](http://127.0.0.1:3210/login)は未設定・未ログイン・招待失効・障害を区別し、明示送信とログアウトを提供します。既定では `AUTH_DISABLED` で、ローカル教材モードを本番認証へ転用しません。メール送信は別途 `ZEIRISHI_AUTH_EMAIL_ENABLED=1` が必要ですが、接続先・`SMTP`承認前は設定しません。学習`API`の本番接続・実メールでの検証は未完了です。認証確認が成功しても `learningBackendReady: false` を返します。

リンクは要求したブラウザーで、最後に要求したものを使います。要求`API`の202は配信確認ではありません。受取後はコードを引き継がず固定のログイン画面へ戻り、認証状態を再確認します。ログアウトは他端末や既発行アクセストークンの即時無効化を保証しません。

宣言`SQL`の正本は `supabase/schemas/learner-access.sql`。隔離`PGlite`で`SQL`とロール権限を検査しており、`Supabase`への適用・`migration`生成・`advisors`・実`Auth`サービス検証とは別です。接続先と費用の承認後に実環境で検証します。停止中の既存プロジェクトは再開・変更していません。

## 開発

```bash
python3 -m pip install -r requirements-dev.txt
python3 -m pytest -q && python3 scripts/coach.py lint
```

オンライン環境の設定値の形式を確認するには、`web` で `npm run preflight:runtime` を実行します。詳細は[実認証・データベース設定の事前確認](../plans/runtime-setup.md)。不足する変数名だけを返し、外部接続や配備は実行しません。
