# PR #6 レビュー追補

## 対応

- 基準は初回登録順で最後に登録された版をcurrentとし、撤回後も旧版へ戻さない。
- 基準未登録のmeasurement-only概念も、`evaluateSubject`で`measurement_preparing`として表示する。
- 通常撤回では真の閲覧履歴を残す契約を維持し、それとは別に管理専用の`disclosure_invalidation`追記recordを追加した。対象owner・存在・概念版・時刻をtransaction内で束縛し、訂正record自体の撤回は通常のrevisionで監査可能にする。

## 境界

管理サービスはlearner HTTPへ公開せず、invalidationは署名や検証者名だけで権限を証明しない。訂正は合成管理入力の検査であり、専門承認・実DB運用の証明ではない。

## 検証

`web`でmastery evidence service test 8件、および`tsc --noEmit`成功。対象テストには基準rollover、measurement-only、誤開示訂正・訂正撤回・不存在target拒否を含む。

主担当レビューで、訂正記録の保存だけでなく評価結果の変化を確認する必要があると判断した。無効化で試験確認が復帰し、その撤回で再び除外されること、過去時点の再計算、別所有者・別概念・版・時刻・非開示targetの拒否、元開示文書の保全を回帰へ追加した。管理主体の認証・訂正根拠の実審査は呼出元の責務であり、文字列だけで承認したとは扱わない。

補強後に主担当がNode 24.20.0で習熟判定・保存の関連35件と型検査を実行し成功した。PR #5の最新修正 `cacdf49` を取り込んだ状態で検証した。GitHubのスレッド解決と本番検収は別途残る。

追加指摘3973632214を採用。開示と訂正の時刻は、検証済みISO文字列の表記一致ではなく同じ瞬間かを比較する。UTCと日本時間表記で同じ開示を訂正できる回帰を既存テストへ追加し、異なる瞬間を拒否する検査は維持した。過去の2指摘は同じコメントIDの位置更新であり、新規指摘として重複修正しない。

指摘3973734718は基準未登録の場合の部分を採用。測定だけの概念は初回登録順で最新の測定scopeを準備中として表示する。登録済み基準がある概念は、その現行版（撤回済みを含む）を正とし、測定の取込だけで置き換えない。撤回した新版から旧版へ戻さない既存契約は維持する。測定だけのv1→v2登録と、撤回した現行基準を維持する既存回帰で確認する。
