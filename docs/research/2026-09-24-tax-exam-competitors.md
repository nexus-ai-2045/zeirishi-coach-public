# 税理士試験学習サービスの競合一次調査

調査日: 2026-09-24。対象は日本の税理士試験向け学習サービス。各社の公開ページで確認できる提供内容を比較した。実利用、教材品質、学習効果、売上・市場シェアは検証していない。「大手」は市場シェア順位の意味ではなく、主要な比較候補という意味で用いる。

## Zeirishi Coach の比較基準

[現行プロダクト仕様](../specs/PRODUCT_SPEC.md)は、合格圏付近の受験生を初期対象に、実務ケースで根本概念を理解し、時間内・ノーヒントの試験問題と遅延復習へつなげる設計。AI師匠は説明・ヒント・対話を補助し、採点と教材公開の最終権限を持たない。MVPは共通データ構造が全11科目に対応する一方、提供教材はパイロット対象の1科目から。仕様冒頭には、学習体験と保存基盤の統合後も機能接続・実利用検証・公開承認が未完了と明記されている。したがって、以下の「自社」は設計上の狙いであり、既に実現・実証した優位性ではない。

## 判断と設計上の優先順位

1. **同質化している領域を前提にする。** AI質問、復習計画、進捗・実力可視化はスタディングの税理士講座に明記されている。これらを「競合にない機能」と表現しない。
2. **実務ケースから独力の試験再現への移行を検証する。** 自社仕様の案件資料、追加質問、本人による説明、別形式の未見問題、遅延再現はまとまった体験仮説である。今回読んだ各社ページだけでは、各社が同等の体験を提供しないと断定できない。まず実際の学習者に1案件を通してもらい、誤概念再発と試験問題への転用を測る。
3. **模試の位置づけを明確にする。** TAC・大原には公開模試と比較の仕組みがある。自社の概念別ミニ模試を科目全体の合格判定に使わない現行仕様は維持し、外部模試の利用条件・年度・採点根拠を確認する。
4. **教材の信頼性を機能より先に見る。** 大手は講師・教材・答練の蓄積が強い。自社の初期1科目は、出典年度・専門レビュー・問題ファミリーの分離が揃うまで「対応済み」と言わない。

## GitHub の先行実装から借りる考え方

以下は各プロジェクトの公開リポジトリで確認した機能・設計の参考例であり、税理士試験への適合性や学習効果を検証した結果ではない。星の数を品質順位として扱わず、コードの再利用はライセンス・保守状態・安全性を別途確認する。

| 先行例 | 公開リポジトリで確認できる方向性 | 本アプリへの適用判断 |
| --- | --- | --- |
| [Oppia](https://github.com/oppia/oppia) | 回答に応じて分岐する対話型レッスンとフィードバック。 | 誤答後の「なぜそう考えたか」を扱う教材設計の参考にする。基盤全体は移植しない。 |
| [Moodle](https://github.com/moodle/moodle) | 問題、採点、学習管理を持つ大規模なLMS。 | 標準的な問題・受験記録の考え方を比較する。初期1案件のためにLMS全体を導入しない。 |
| [Artemis](https://github.com/ls1intum/Artemis) | 演習、フィードバック、分析などを統合した学習環境。 | 回答の証拠と指導の役割分離を参照する。機関向けの運用をそのまま持ち込まない。 |
| [OpenTutor](https://github.com/zijinz456/OpenTutor) | README上は概念グラフ、診断的なクイズ、対話型の指導を掲げる。 | 概念マップと個別対話の接続を比較する。READMEの機能説明を実証済み効果とは扱わない。 |

この比較で優先すべき作り込みは、技術スタックの追加ではなく、現在の保険料案件で「全体の位置→判断→誤答理由の対話→別問題での独力再現」が迷わず一周できること。先行例に似た機能の有無だけでは差別化も学習効果も主張しない。

## 未確認と次の調査

- 各サービスの無料体験や実際の学習画面は操作していない。特に「実務ケース型の対話」「本人の説明・反例の評価」「ヒント付き正答と独力正答の区別」は公開ページからだけでは横比較できない。
- 提供者の市場シェア、受講生数の比較、合格率の比較は今回の一次調査では行っていない。各社の自己申告数値は母数・定義が異なりうる。
- 自社の効果は未検証。初期1名の4週間パイロットは体験上の問題発見には有用だが、一般的な合格率改善の証明にはならない。
- 次は各社の無料体験で1つの論点について「誤答→質問→復習→別問題」の実画面を観察し、同じ論点を自社パイロット案件で比較するのが最小の追加調査。
