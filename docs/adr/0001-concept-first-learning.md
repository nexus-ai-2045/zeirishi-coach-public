# ADR 0001: コア概念と実務ケースを往復する学習

状態: 採用（試用版への適用。本番教材の専門承認とは別）

## 背景と決定

利用者は、個別クイズに入る前に各科目の概要とコア概念を理解したいと明示した。全員に同じ講義の順次受講を要求せず、全体像・コア概念・具体的な取引・実務ケースを往復できる構成を採用する。

今回の実装はローカル固定教材版の簿記のみ。学習一覧に全体像と選択可能な3概念、取引の状態比較、相談開始を接続し、相談中も概念を開ける。説明を閉じても問題への入口は維持する。閲覧・スキップ・シミュレーション操作は習熟証拠として保存しない。

## 代替案と責務境界

- 問題だけを提示する方式: なぜその処理になるかの全体像が不足するため、単独では採用しない。
- 全員に順番通りの基礎講義を必須化: 既習者の負担になるため採用しない。
- 全科目を即時追加: 未審査の説明を正式教材として配布しない。今回の例は専門確認前の試用コンポーネントに限定する。

正本は製品仕様 `docs/specs/PRODUCT_SPEC.md`、今回の設計判断は本ADR、実装は `web/src/components/BookkeepingIntro.tsx`。運用者による教材承認・内容拡充は別の受入条件であり、本部が統合と検証を担当する。

## 受入条件

2026-09-23追記: 最初の簿記体験に、資産と負債を同じ10万円目盛りで比較する操作連動図を採用。借入と備品購入の状態を切り替え、利益との違いを一枚で示す。既存React/CSSで実装し、動画サービス・APIキー・新規依存は追加しない。色に加えて名称・金額と読み上げ用説明を持たせ、動きを減らす設定に対応する。これは入門体験の局所改修であり、ホーム全体の動線整理や保険料の資料表示を完成扱いにしない。

概念を好きな順で選択でき、取引の状態が表示に反映される。導入を閉じて再度開ける。相談開始後も概念へ戻れる。既存の回答・保存契約を変更せず、APIキーや新規サービスを要求しない。実AI・専門教材・本番配備をこの変更で完了扱いにしない。
